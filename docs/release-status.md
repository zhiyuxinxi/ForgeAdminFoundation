## 源码存在与运行可用的区别

当前仓库包含多端源码、服务、数据库脚本、示例配置及相关测试。首次公开与本轮文档更新没有执行全新环境构建、数据库初始化、首次登录、完整业务流程或生产部署验收。

因此，本版本不能宣传为已经验证的一键安装包、无缺陷发行版或覆盖所有客户端的稳定交付包。维护仓库中的已有运行结果不自动适用于清理过数据和配置的公开快照。

## 当前需要优先确认的上手事项

| 事项 | 源码事实 | 对使用者的影响 |
| --- | --- | --- |
| 首次登录客户端种子 | 公开基础 SQL 提供演示管理员；在基础 SQL 与必要种子中未见 `sys_client` 初始化记录，而管理端认证会查找启用客户端 | 空库初始化后的完整登录链路需要补充核实；仅有账号密码不能保证登录成功 |
| Redis 示例 | Redisson 现在引用 Spring Redis 的主机、端口、数据库和密码 | 修改 Spring Redis 配置后由同一来源消费，仍需验证自己环境连接 |
| 流程服务库名 | 流程开发示例为 `forge_flow`，管理服务为 `forge_admin` | 使用共享库方案时要显式对齐；分库需要额外初始化与联调 |
| 多前端工具版本 | PC、H5、报表分别使用不同版本的 Vite；根包管理器声明与容器 UI 示例也不同 | 应分别安装并记录结果；不能用一个旧 README 版本要求覆盖所有模块 |
| 报表与 H5 | 分别依赖报表服务、移动服务，登录/SSO 与数据库准备未做本次验收 | PC 能打开不代表这些客户端已可用 |
| 部署与外部集成 | 公开代码不带生产凭据、模型额度、业务数据或部署回执 | 模型、文件、消息、协同连接等需要自行配置与验证 |

这些是基于当前代码的明确差异或待验事项，尚未完成真实环境安装验证；没有把每一项都当作已复现的运行故障。

## 容器示例的适用边界

仓库保留 [docker](../docker/) 和 [docker-forge-admin](../docker-forge-admin/) 两套历史示例。当前不把它们作为新用户的一键安装入口，原因包括：

- 两套 Compose 已同步维护主干的统一初始化入口；已有卷不会重新初始化，升级前需核对脚本参数、迁移记录和备份。
- SQL 保留公开演示身份；容器说明、环境占位值和实际数据库身份需按部署方配置核对，首次登录仍未在本次验证。
- `docker-forge-admin` 的初始化挂载指向现有 `init-sql`，但整套构建、数据库迁移、登录和前端访问链路尚未做本公开版本的运行验收。
- 容器构建文件已同步维护主干；依赖安装和容器构建未在本次执行，使用者仍须按实际前端版本验证。
- 默认数据库、Redis 及应用端口映射需要按自己的网络环境限制；使用前必须替换示例口令并检查访问范围。

本轮已同步这些配置和源码，没有构建镜像或运行安装。当前源码开发入口见[本地开发指南](getting-started.md)。

## 公开更新方式

日常开发主要在维护仓库进行，公开仓库按阶段同步经过整理的源码快照。更新频率可能低于维护仓库；当前没有承诺固定同步周期。

每次公开更新应同时提供：

1. 公开提交或标签、同步日期、变更摘要。
2. 本次实际增加/修改的能力及配置、数据库迁移影响。
3. 已执行的验证与未覆盖事项。
4. 已知问题的关闭依据或保留状态。
5. 对应文档和来源/许可信息的更新。

新版本可能保留尚未修复的问题。维护仓库已经修复但尚未同步的内容，不能作为当前公开版本已经修复的依据。使用者升级前应阅读记录、保存自己的修改并备份实际业务数据；不能用公开初始化脚本覆盖已有业务库。
