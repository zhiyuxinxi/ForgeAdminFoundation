# 编码规范
## 1. 命名
- 类名：大驼峰，见名知意
- 方法名：小驼峰，动词开头
- 常量：全大写下划线分隔
- 抽象类以 Abstract 或 Base 开头
- 测试类以被测类名开头，Test 结尾
- 禁止拼音、中英混拼命名
## 2. 异常处理
- 业务异常使用自定义 BusinessException，携带错误码
- 系统异常向上抛出，由统一异常处理器兜底
- 禁止吞掉异常（空 catch）或把真实失败伪装为成功；业务/系统异常默认按原语义向上传播。
- 仅对明确可恢复的失败做局部降级，捕获范围包住实际可恢复调用，不能把后续授权、校验和持久化也吞掉。禁止为兜底捕获 `Throwable` 或 JVM `Error`。
- 日志由负责处理该失败的边界记录，保留可定位的安全信息；不要在每层重复记录同一异常。
## 3. 日志
- 按排障需要记录操作、结果和关联标识，不默认输出请求体、令牌或用户输入。
- 日志级别对应实际影响；堆栈与异常消息仅在确认不会暴露敏感值的受控服务端日志中记录。可恢复的批量降级汇总失败数量与安全原因，避免逐条刷屏。
- 禁止在日志中打印用户敏感信息
## 4. 其他
- 写接口必须考虑幂等
- 涉及并发场景必须说明同步策略
- 魔法值必须定义为常量
## 5. git提交规范
- 禁止 master 分支变更：编码前检查当前分支，master 上立即停止
- 自动 Commit：每个 task/fix 完成后自动 commit，保持一个 task 一个 commit
- Commit 必须可编译：commit 前执行编译检查
- 禁止自动 Push：push 由用户主动触发，保留审查机会
- Message 格式：[<变更名>] <中文简述>

## 6. 数据库 SQL 规范
### 6.1 租户 ID 规则（重要）
- **运行时业务数据**的租户来自已认证且已授权的上下文；禁止固定 `tenant_id=1`，禁止直接采用客户端传入值。
- **默认租户种子**（内置字典、配置）的迁移约定为 `tenant_id=1`；不得使用 `0` 假装跨租户共享。其他租户的数据按自身租户隔离。
- **过滤边界**以当前 ORM 配置及 Mapper SQL 为准，不受拦截的表、异步任务和跨服务调用必须显式保持授权语义，禁止笼统声称所有 SELECT 均受保护。
- **排查**字典为空时核对当前租户、种子所属租户及实际查询，不通过把所有业务数据改成 `1` 修复。

### 6.2 查询运行兼容
- SQL必须兼容当前数据库及实际MyBatis、JSqlParser、租户/数据权限/分页插件链；XML格式合法、Java编译或数据库直接执行都不证明插件可解析和改写。
- 修改查询时，用真实参数产生BoundSql，验证实际动态分支、列表/分页和结果语义。当前解析链存在限制时，NULL安全比较使用`(a = b OR (a IS NULL AND b IS NULL))`等价写法；不盲用`<=>`，也不将版本限制扩大为所有SQL永久禁令。锁语句与分页count按实际插件核对。
- 保留NULL、租户、逻辑删除、去重和排序语义；不得通过关闭拦截器或移除过滤修复解析失败。

### 6.3 其他 SQL 规范
- 所有业务表必须包含基础字段：`id`, `tenant_id`, `create_by`, `create_time`, `create_dept`, `update_by`, `update_time`
- 使用 `utf8mb4` 字符集，`InnoDB` 引擎
- 为高频查询字段创建索引，组合索引遵循最左前缀原则
- 禁止将数据库凭据提交到仓库
- Flyway 迁移脚本中禁止直接写业务 `${...}` 模板；确需入库时使用 `CONCAT('$', '{token}')` 拼接，并用 `rg -n '\$\{[^}]+\}' forge-server/db/migration` 确认无残留

## 7. 前端规范
### 7.1 字典使用
- 下拉选项、状态标签等**禁止硬编码**，必须使用字典组件
- 加载字典：`const { dict } = useDict('dict_type_1', 'dict_type_2')`
- 表单下拉：使用 `DictSelect` 组件，或在 editSchema 中通过 `computed` 引用 `dict.value['xxx']` 作为 `props.options`
- 表格标签渲染：使用 `DictTag` 组件，配合字典的 `listClass` 字段自动映射颜色
- Schema 必须定义为 `computed`，确保字典数据异步加载后选项能响应式更新

### 7.2 图片/文件字段渲染
- `imageUpload` 组件存储的值是 **fileId**，不是完整 URL
- 表格列渲染图片时，**必须使用 `getFileUrl()` 将 fileId 转换为下载链接**：
  ```js
  import { getFileUrl } from '@/utils/file'
  // 正确
  h(NAvatar, { src: getFileUrl(row.logo), size: 32, round: true })
  // 错误 - fileId 无法直接作为图片 src
  h(NAvatar, { src: row.logo, size: 32, round: true })
  ```
- **鉴权图片必须使用 `AuthImage` 组件**：
  - 文件下载接口 `/api/file/download/{fileId}` 需要鉴权（Bearer Token）
  - 直接用 URL 作为 `<img>` 或 `<NAvatar>` 的 `src` 属性**不会携带 Authorization header**，导致 token 无效错误
  - **解决方案**：使用 `AuthImage` 组件，它会通过 fetch 带 token 获取图片并转为 blob URL：
  ```js
  import AuthImage from '@/components/common/AuthImage.vue'
  // 正确 - AuthImage 自动处理鉴权
  h(AuthImage, {
    src: row.logo,
    imgStyle: { width: '32px', height: '32px', borderRadius: '50%', objectFit: 'cover' }
  })
  // 错误 - NAvatar src 不会带 token，接口返回"未能读取到有效 token"
  h(NAvatar, { src: getFileUrl(row.logo), size: 32, round: true })
  ```

### 7.3 操作列按钮
- 操作列按钮超过 2 个时，`AiCrudPage` 会自动将多余的折叠到"更多"下拉菜单
- 按钮顺序安排：最常用的操作放前面（会被内联显示），低频操作放后面（收入"更多"）
- 操作列宽度需根据按钮数量合理设置：2个内联按钮约 150-180px

## 8. 后端架构规范
### 8.1 循环依赖
- Service 之间禁止相互注入形成循环，允许符合职责的单向依赖。
- 跨 Service 协调由明确的应用服务承担；Controller 只处理协议、参数校验和调用，不承接事务与业务编排。
- 不以 `@Lazy`、静态 Bean 查找或通用工具类隐藏循环；拆出有明确拥有者的职责或面向调用方的窄接口。

### 8.2 API Key 等敏感字段
- 接口返回中包含 API Key、Secret 等敏感字段时，**必须脱敏处理**
- 脱敏方式：保留前4后4位，中间用 `****` 替代

### 8.3 模块、包、类和方法的职责
- 设计前查看相关现有代码，说明本次能力的拥有者、调用方向和边界；按业务职责与变化原因组织包，不按文件数量机械分包。
- 业务运行逻辑不得依赖代码生成器的模板、生成实现和设计态内部类型；复用真实运行能力时由对应运行模块或窄公共契约拥有，禁止业务反向调用生成器内部实现，也不为消除一条依赖创建万能公共模块。
- 类只承担内聚职责，方法只完成一个可说明的步骤。新增行为遇到已有大类/长方法时，先提取本次涉及的完整职责，保持公共接口及关键语义；不能继续堆分支或整体搬到新巨类。
- 重复逻辑按共同业务语义与变化原因决定复用；不能只因文本相似抽成 `CommonUtils`。抽取后调用方不应继续知道实现细节或传入大量不相关状态。
- 公共方法和通用模块不得夹带具体客户或具体业务场景的实现、业务状态分支、字段名单及专用业务方法。具体业务由其领域模块拥有，通过明确参数或窄契约消费公共能力；不能将客户实现搬入底层后冒称公共复用。
- 方法之间不得形成循环依赖；模块、包和类的调用方向必须与职责归属一致。设计与审查须核对本次变更和直接消费者的调用链，拒绝相互回调、反向依赖，以及用 `@Lazy` 或静态 Bean 查找隐藏循环。已有静态兼容门面只能单向委派明确拥有者，不能持有第二套状态或成为新代码入口。
- 使用现有静态配置同时检查类规模、方法数、方法长度、复杂度和耦合，并人工核对内聚与依赖方向。阈值见 `tools/quality/README.md`，不是可填满的配额；低于阈值不能证明设计合理。

### 8.4 关键代码边界
仅核对本次实际涉及的边界，并在现有变更说明中留下代码位置与验证依据。

| 边界 | 必须保持的语义 |
| --- | --- |
| 身份、权限、租户 | 以可信身份与租户确定主体；对象权限、字段可写范围、状态操作权限不可用“已登录”替代；重构后原权限入口仍执行。 |
| 输入与输出 | DTO 白名单、空值/空集合/缺失值按合同区分；不能批量复制请求覆盖所有权或状态；输出不得泄露密钥、内部异常或跨租户数据。 |
| SQL 归属 | 业务条件查询写在命名清晰的 Mapper/XML，Service 不拼查询 SQL；保留参数化、租户/数据权限/逻辑删除语义。动态标识符只能来自已校验元数据，不能直接拼用户输入。 |
| 事务与状态 | 应用服务确定本地原子边界；提取类后保留有效代理与回滚语义，不能依赖失效的同类自调用。状态迁移同时校验预期旧状态与授权，失败不能留下部分成功。 |
| 并发与幂等 | 根据实际竞争使用受影响行数、版本/CAS或唯一约束；不能仅先查后写。幂等键限定租户、业务对象与本轮操作，不吞唯一冲突伪称成功。 |
| 跨服务契约 | 明确调用方/被调用方拥有的数据、错误与超时语义；超时代表结果可能未知，不能盲目重复非幂等写入或用本地回滚假定远端已撤销。 |
| 异常与降级 | 只降级明确可恢复步骤；授权、校验和必要持久化失败向上传播。保留原始失败证据，降级日志脱敏、有限且可定位。 |
| 资源生命周期 | 流、连接、临时文件、锁与线程资源明确创建者和释放者；成功、异常及取消路径均有必要释放，不清理其他任务或调用方拥有的资源。 |

进度订阅由同一owner登记和释放；同一对象多个客户端不能互相覆盖，旧连接退出只能注销自己的订阅。即时SSE不替代持久任务状态，也不自动具备跨实例广播能力。

需要设计器维护时，先明确设计器元数据与代码持久化映射、业务校验、权限、扩展的所有权。`BusinessObjectDesignerService.saveDesigner`保存草稿；正式应用由`BusinessApplicationRuntimeService`按`lastPublishVersion`消费发布快照，业务不能手写发布状态或把草稿当正式配置。代码表单按实际需要实现`forge-lowcode-api`的`BusinessCodeFormProvider`，它不替代普通CRUD或发布服务。用真实保存→发布→后端运行消费证明草稿隔离和再次发布/生成时扩展保留，记录对象/配置/版本；不承诺任意Java反向转换，不为普通CRUD强制接入设计器。

### 8.5 设计、编码、检查与修复的实际执行
1. 设计在已有 spec 中明确上述职责、依赖和实际涉及的关键边界，不新增平行合同或治理文件。
2. 编码与生成按职责落地，修改旧代码不能以“历史如此”继续扩张巨类；结构整改不能削弱接口、权限、事务及失败语义。
3. 对本次新增/修改 Java、授权具名整改文件及有依据的直接消费者，使用 `tools/quality/README.md` 中的现有 `fast` 检查。保留原始报告的 rule/path/line、`code/structure` 分类和工具错误；未执行不能报通过。
4. 检查发现交回当前编码/修复模型，先结合真实职责确认根因，再修复当前范围问题并只重验受影响部分。禁止放宽阈值、删规则、加抑制、扩大排除或改断言凑通过。误报保留原结果及具体依据。
5. 重构验证保留必要的前后输出、接口与关键边界对照，复用未变化的证据。编译通过或告警数量下降不证明根因消除；仍需整改的具名结构问题必须明确未完成，不能全部转 TODO 后宣布完成。

### 8.6 公共能力归属与生成代码边界
设计、生成和修改当前后端时，先在既有变更说明中列明真实源码 owner、公开方法与安装消费者，区分已有能力、公共接口缺口和必须保留的业务规则。未读取当前源码不得猜 API；以下按本次实际功能消费，不新增平行治理系统。

- **身份与成员：**权限、办理人、接收人和历史关联使用认证上下文及稳定 userId，姓名只作展示快照，不能按姓名或去括号姓名识人。消费 starter-core 的 `com.mdframe.forge.starter.core.identity.TenantMemberDirectory`，由 system 装配：`findActiveMembers(Collection<Long> userIds, Long directOrgId)` 最多 500 个输入 ID，组织参数可空，空集合返回空；`findActiveMembersByOrg(Long directOrgId, String keyword, Long afterUserId, int limit)` 必须指定直接组织，limit 为 1..200，按返回的最后 userId 续页。两方法仅使用可信当前租户、有效成员/账号/租户和当前有效直接组织关系，返回 `TenantMember(userId, username, displayName)`；缺失或停用 ID 被略过，必须全员有效的写入应比对请求 ID 集合。业务仍校验动作与组织范围、叠加岗位/经理/抄送规则；不能把该目录当权限授予。`sys_user.tenant_id` 是默认租户而非当前成员资格，业务不得联查身份表重建成员算法或依赖 plugin-system 实现；必要个人展示读模型可在有效 ID 验证后保留，不能据此扩张身份 API。历史记录保留稳定 ID/展示快照，不能因现时停用而消失。
- **组织与权限缓存：**祖先链由组织 owner 按当前租户和父节点在服务端派生，业务不能提交可信 ancestors 或调用 system 内部树维护器。涉及已授权权限配置修改时，缓存刷新使用现有 `DataScopeCacheRefresh.afterCommit(IDataScopeService)`，不得在事务未提交时刷新让其他线程重新缓存旧配置。
- **字段与状态：**创建由服务端设置初态，普通编辑使用可写字段白名单，保留余额、累计量、审批状态、签字和历史等受控字段；动态 Map/分区保存也不例外。确认/签署等动作核对可信主体、原记录范围、预期状态/version，并检查实际影响行数。审批中的内容仅经允许节点修订，不能通过普通 edit 旁路。
- **流程与普通任务：**复用现有 FlowClient、BPMN 任务/抄送节点、调度与普通待办能力；业务不直接维护 `sys_flow_*`/Flowable 表，不创建第二套通用任务执行器。业务状态映射、特殊轮次、审批后入账归业务。列表/详情/导出保持只读，状态修复与推送由回调、既有调度或明确授权动作执行；生产历史只能来自真实事件，未执行不得记成功。
- **会签：**汇合校验本轮全部必需义务有效批准，不能只数 pending；驳回重提恢复所有尚未有效批准的义务。并发办理先锁定聚合后读取节点或采用等价 CAS/current-read，禁止无版本整体覆盖审批 JSON。旧流程实例回调不能覆盖当前实例或使已过账状态回退。
- **字典与文件：**字典的存储、租户取值和展示翻译归公共 owner，稳定业务状态编码及迁移仍归领域；组合目录与库存读模型不能复制字典维护体系。文件用统一 FileManager/权限契约验证真实 fileId、操作者和动作；请求名称/大小/类型/URL 不代表存在或授权。业务只增加附件用途规则，删除业务记录不擅自删除共享附件。
- **数量与幂等：**库存/金额/剩余数量归领域唯一 owner；多个入口共用原子消费及流水事务，不能先查余额再覆盖重算。普通属性更新不得回写旧余额；自动累计在成功过账时计算。幂等比较规范化内容、对象、方向/数量及主体范围，同键异内容拒绝，真正重试返回原结果，不靠短时防连点或唯一键替代语义。
  现有 generator 数量服务使用 Long/BIGINT，COMMIT 依赖已有锁；它不是可供业务反向依赖的 DECIMAL 直接出库公共 API。先核单位、精度、动作语义，不能转整型、伪造锁或建第二账本来迁就接口。
- **编号：**原子取号复用已存在的序列或 BusinessCodeGenerator，业务保留格式和年度/装置分组；禁止 COUNT+1、无锁 MAX+1，序列键含可信租户与分组，迁移对齐既有最大编号水位和唯一约束。不同编号契约不能因都返回字符串就互换。
- **真实事务与批量：**事务绑定实际使用的 DataSource，默认库注解不能承诺外部库回滚；依赖已提交记录的异步工作在提交后投递。批量关联校验按租户/组织合并查询并批量写子表，数据库分页且不固定截断全量计划；保留既定导入原子性。
- **运行元数据：**导入、发布和执行一致保留自增/服务端生成/调用方提供的主键策略，以及固定逻辑删除值/主键墓碑策略。已有表 `EXISTING/sourceTable` 保留真实列与 `autoIncrement`，不强加自增 ID 或不存在的审计列，更新不得改主键。`LowcodeLogicDeleteStrategy.deletedValueMode=VALUE` 绑定固定 `deletedValue`，`PRIMARY_KEY` 仅按校验后的元数据执行主键列赋值；禁止把 SQL 片段塞到 `deletedValue`。实际基线未装配对应契约时先同步公共 owner，不在业务复制删除引擎；不支持的形态在导入或发布时明确拒绝。
- **定向验证：**按实际改动覆盖同名不同 ID、改名、跨默认租户成员、禁用成员、普通保存注入终态、原对象越界、同键异内容、编辑与过账竞争、会签重提/并发、实际数据源中途失败、提交后调度及墓碑重建等相关路径。静态、编译和运行证据分开报告，不为本节机械重跑无关模块。

### 8.7 普通维护台账的原生后端默认合同
生成或按统一标准整改普通可维护台账时，在既有 API/验收说明中逐项对应真实分页、条件查询、详情、新增、编辑、单条删除及其权限、参数、响应和失败行为，不等产品逐项补充基本操作。只读查询、归档、审计流水或审批/签字约束来自明确业务规则；缺少删除接口不构成禁删依据，也不能据此宣称普通台账完整。

- 按原生分层实现：Controller 负责协议、鉴权、DTO 校验与委托；应用/领域 Service 负责引用、状态和写入规则；Mapper/XML 负责查询。复用 `PageQuery/pageNum/pageSize`、数据库分页、稳定排序和查询重置后的无条件语义，分页前应用可信租户和数据范围；详情、编辑、删除校验同一原对象范围。
- 新增/编辑 Command、Query、VO 分离，DTO 字段及集合校验在真实入口生效；普通请求不授予租户、所有者或终态写权限。ID、字典 code、日期/时区、空值及分页包络按当前公共序列化与前端组件合同对齐，禁止用展示文本替代稳定 ID。
- 单删必须校验动作权限、可信租户/数据范围、当前记录状态及真实引用关系，按现有逻辑删除与事务机制执行并检查影响行数。记录不存在、越界、被引用、审批中或并发变化按真实规则返回项目统一的可理解失败原因，不吞异常或用成功审计掩盖失败；不能只隐藏按钮，也不能虚构引用关系一律禁删。
- 普通多选删除可复用已有单删接口与前端公共逐项处理，逐项保留成功/失败及失败原因，不要求每个实体新增 `removeBatch`。确需后端批量端点时才约定 ID 上限、逐项校验、整批原子或部分成功语义；不得循环忽略单删失败后返回全成功，既定整批事务也不能偷偷降为部分提交。
- 字典、组织/成员、附件、序列、审计及错误处理复用 8.6 的真实公共 owner；业务只叠加用途、引用和状态规则。保留既有附件、子表、签字、导入导出能力，不复制身份表查询或为台账再建一套公共服务。
- 定向验证对应实际改动：正常分页/过滤与 CRUD、无权限/跨租户/越界详情和删除、被引用/受限状态删除、零行写入及多选部分失败（采用逐项处理时）。接口缺失、静态检查、编译和实际行为验证分别报告；不把本节扩大成无关全模块重测或新治理机制。


### 8.8 异步、调度、外部调用和附件的实际入口
只在需求涉及该能力时应用；本节不要求普通CRUD额外建设异步或任务系统。

- **容器停机：**Java 启动脚本经 shell 展开参数时必须用 `exec java`，让停止信号到达 JVM。容器停止宽限期须覆盖应用任务排空及资源关闭时间；公共 Compose 默认 60 秒，实际调整应用等待配置时同步核对。验证实际进程和停止退出结果，不能以应用内 shutdown 单测或启动成功代替容器停机证明。
- **短时异步：**使用应用中已配置的受管理执行器。新增执行器确有必要时明确线程/队列上限与拒绝处理、停机等待及任务失败状态；禁止每个请求或业务Service自行new线程池，禁止把内存队列宣称为重启可恢复。数据库提交后才执行依赖该写入的任务；回滚不得派发。拒绝发生在afterCommit时数据库已提交，必须留下可重试失败或明确反馈，不能假定回滚撤销了任务记录。任务取消/超时区分未开始、运行中与结果未知，不伪造成功。
- **上下文：**`forge-starter-tenant`的`com.mdframe.forge.starter.tenant.datasource.TenantBusinessDataSourceTaskDecorator.decorate(Runnable)`捕获租户、数据源和`ExecutionIdentity`并在finally恢复；它不传播Locale。异步导出/通知另捕获`LocaleContextHolder.getLocaleContext()`并在finally恢复旧值。持久调度不能复制在线用户凭据；由既有执行身份与任务所属租户恢复授权。
- **提交后的失败回写：**afterCommit仍可能绑定已提交事务的资源，持久化失败状态应经独立代理的REQUIRES_NEW等明确事务边界，不依赖同类自调用或原事务继续提交。入队和重试用持久请求/批次标识及预期状态进行CAS，拒绝、超时或旧完成回调只能影响自己的批次；等待用户确认与已请求处理须可区分。停机先等待/处理尚未开始的任务，再销毁数据源等依赖；运行中或远端结果未知不能直接当作安全取消并重复副作用。
- **持久调度：**复用`forge-plugin-job`注册/调度/日志与`forge-starter-job`注解。现成Handler入口为`com.mdframe.forge.plugin.job.executor.IJobExecutor.execute(String param)`，使用`@JobHandler`注册后通过现有任务管理绑定；Bean直连采用`@ScheduledJob`。业务拥有幂等键、分批游标、成功/失败与重试规则，异常向调度器传播；不能另写sleep轮询或直接维护Quartz表。审批待办仍使用FlowClient/BPMN，不混成普通定时任务。
- **外部HTTP：**复用`forge-starter-outbound`的`com.mdframe.forge.starter.outbound.client.SecureOutboundClient.execute(OutboundRequest)`；请求提供真实scene、URL、方法及有限的connect/read/write/call timeout，沿现有白名单与目标校验。需取消时使用`execute(request, Consumer<Runnable> cancellation)`，null回调表示调用已结束并解除注册。读取`OutboundResponse`的实际状态，不把HTTP失败包装成功，不关闭平台借出的客户端。非幂等写入超时视为可能已执行，按对方幂等键/查询协议恢复，不盲重试、不泄露凭据与响应敏感内容。
- **流程未知结果：**使用现有`FlowClient`带startRequestId/previousProcessInstanceId的启动合同和`getProcessStartStatus(businessKey, startRequestId)`查询；`FlowStartOutcomeUnknownException`不能当作确定失败重开实例。本地业务链接补偿仍由已有拥有者处理，普通模块不复制流程恢复器。
- **附件：**`forge-starter-file`的`FileManager`拥有上传/下载/访问链接与删除；元数据来自真实fileId。关联前通过`FileMetadataPersistence.checkPermission(fileId, userId)`核当前读取权限，修改/删除使用`checkWritePermission`及对应公共入口，不能从public可读推导可写。`getMetadata/getFileMetadata`只是取元数据，不能单独当授权证明。业务拥有必填、类型/数量与引用规则，删业务引用不自动删共享物理文件。
- **导入导出：**复用`ExcelImportService.importData(file, configKey, DTO.class)`与`DynamicExportEngine.export(response, configKey, queryParams)`及现有字典/Excel元数据。持久化前对成功解析DTO执行与新增相同的实际校验；成功解析不等于数据库导入成功，原子导入任一行失败需回滚，部分导入须有明确逐项结果。异步导出沿上述租户、语言、失败与资源释放合同，不能绕分页上限查全表替代专用导出。

本轮只验证实际涉及的拒绝/回滚、上下文隔离、超时/失败、权限与字段边界，不为本节自动添加全量回归。知识库容量/拒绝/停机与重启恢复的源码和运行状态见当前专项交接；规范本身不证明机制已修复或运行端已更新。

## 运行合同与跨层正确性

以下要求只应用于本次改变的路径，不是每次必跑清单：
- 先核实际import/export、公开签名、依赖版本和配置消费者。历史例子只作线索，不编造接口或复制模块私有实现。
- 前后端共同核对ID、金额/精度、日期/时区、null/未传/空值、分页和错误包络；合法语法或两端各自单测不能替代真实接线。
- 权限、校验、事务、缓存与异步通过实际入口/代理生效。相关多写/状态变化检查回滚、受影响行数、并发和幂等；超时保持结果未知，不盲目重放副作用。
- 异步回填/筛选/切换/卸载按请求与对象归属更新，旧结果不覆盖新页面；提交失败保留输入并恢复可操作状态。按实际需求取消或忽略过期请求，不强造通用请求框架。
- 文件、连接、监听器、队列和批量操作明确上限及成功失败释放路径；不以小样本推断无界操作安全可用。
- 可接受降级须有业务依据，必要写入或权限失败不得返回成功。错误返回与日志关联且脱敏，HTTP状态和业务结果按当前客户端合同共同解释。
- 具体有效验证按自动化测试标准选择，测试期望来自需求/稳定合同，不复制实现假设或mock掉被验证机制。
